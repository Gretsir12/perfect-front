# Замена изображений

Все фотографии, логотипы, фоны и социальные обложки сайта собраны в [src/content/images.json](./src/content/images.json). Каждая запись содержит `src` — путь к файлу внутри `public` — и `alt` — краткое описание изображения. Компоненты сайта менять не требуется.

## Найти нужное изображение

В корне проекта выполните:

```sh
npm run images:catalog
```

Откройте полученный `artifacts/images-catalog.html` в браузере. Каталог содержит превью, поиск, ключи, размеры и команды замены для 100 мест использования. После изменений запускайте команду снова, чтобы обновить превью. Каталог работает локально и не является административной страницей сайта; после переноса проекта его нужно сгенерировать заново.

| Место на сайте | Ключ в JSON |
| --- | --- |
| Логотипы шапки и подвала | `brand.header`, `brand.footer` |
| Слайды главного экрана | `home.slides` |
| Фото блока о компании на главной | `home.about.primary`, `home.about.secondary` |
| Реализованные проекты | `home.projects` |
| Трансформация пространства | `home.transformation` |
| Иконки замера, доставки, монтажа | `home.process` |
| Фоны секций и модели производства | `backgrounds` |
| Обложки внутренних страниц | `pages.<адрес>.hero` |
| Обложка и галерея изделия | `catalog.<адрес>.cover`, `catalog.<адрес>.gallery` |
| Обложка услуги | `services.<адрес>.cover` |
| Обложка статьи | `articles.<адрес>.cover` |
| Изображения по умолчанию | `defaults.hero`, `defaults.social` |

Индексы массивов в командах начинаются с нуля: первый слайд — `home.slides.0`. Полный точный ключ можно скопировать из каталога.

## Заменить одной командой

```sh
npm run images:replace -- home.about.primary "/путь/к/новому-фото.jpg" --alt "Стеклянная перегородка в интерьере"
```

Команда копирует файл в `public/images/uploads`, присваивает имя по содержимому и обновляет только выбранную запись. Это помогает избежать старой картинки из кеша. Исходное изображение сохраняется. Если `--alt` не указан, прежнее описание сохраняется; при смене сюжета обновите его.

Поддерживаются JPG, JPEG, PNG, WebP, AVIF, GIF и SVG. Используйте подготовленные изображения: для фото обычно подходят WebP/AVIF/JPEG, для прозрачных логотипов — SVG/PNG. Сохраняйте подходящие секции пропорции: фоновые фото и карточки могут обрезаться по краям.

## Заменить вручную

1. Положите новый файл в `public/images/uploads` под новым именем.
2. Найдите запись в `src/content/images.json` и поменяйте `src` на `/images/uploads/имя-файла.webp`, а `alt` — на описание.
3. Выполните `npm run images:check`.

В JSON указывайте исходные пути, без URL-кодирования и без префикса `public`. Внешние URL не поддерживаются этим каталогом. У декоративных фонов оставляйте `alt` пустым. Если один файл используется в нескольких записях, замена одной записи не меняет остальные. Обложки изделий, услуг и статей используются соответствующими карточками, страницами и метаданными для публикации ссылок.

Чтобы добавить или переставить слайды и фотографии галереи, измените порядок или состав соответствующего массива объектов `{ "src": "…", "alt": "…" }`. В `home.slides` должен оставаться хотя бы один слайд. Иконка вкладки браузера хранится отдельно в специальном файле Next.js `src/app/favicon.ico`.

## Проверить и опубликовать

В режиме `npm run dev` изменения подхватываются автоматически. Проверьте страницу на компьютере и телефоне. Для production выполните `npm run build` и опубликуйте сборку вместе с новыми файлами из `public`. Проверка изображений запускается перед сборкой и останавливает её при отсутствующем файле или неподдерживаемом формате.

Команды меняют локальный проект; действующий сервер они самостоятельно не публикуют.
