## Оставшиеся замечания

### P1 — ограничение частоты заявок

Размер тела теперь ограничен, но ограничение частоты обращений к `/api/leads` отсутствует. Honeypot не мешает прямым POST-запросам. При настройке SMTP массовые запросы могут создавать множество писем. Ограничение следует настроить на сервере/ingress либо через общее хранилище счётчиков для нескольких экземпляров приложения. Конфигурации инфраструктуры в репозитории нет.

### P2 — управление главным слайдером

`HeroImageSlider` переключает кадры автоматически, но `.hero-slide-dots` скрыты CSS. Системный reduced motion учитывается при запуске таймера; доступной кнопки паузы у главного слайдера пока нет. Стоит добавить видимые элементы управления и реакцию на изменение системной настройки во время просмотра.

### P2 — вес статических ресурсов

В `public` на момент аудита 272 файла общим объёмом около 363 МБ. Есть архив RAR ~64 МБ, видео MOV ~48 МБ, ZIP ~13 МБ. Наличие этих файлов не означает, что браузер загружает их при открытии страницы, но они увеличивают объём репозитория/публикации и доступны как статические ресурсы. Фон `original-home/marius.png` весит ~4,7 МБ и загружается CSS без оптимизатора Next Image. Следующий шаг — отделить исходные материалы от публикуемых файлов и подготовить сжатые версии фоновых текстур.

### P2 — каскад CSS

`globals.css` содержит несколько поколений оформления и неиспользуемые селекторы старых секций. Общие текущие правила вынесены в `shared-site.css`, но старый каскад ещё требует отдельной очистки с визуальными проверками. Новые общие изменения следует вносить в общий файл, а не добавлять отдельные варианты для страниц.

### P3 — соответствие старых адресов

Редиректы сохраняют query-параметры, но правила по префиксу сводят вложенные старые URL к странице раздела. Для точного соответствия каждой старой страницы нужен перечень её адресов и новых целевых страниц.
